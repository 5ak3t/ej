fitting; the final suites were scored once for it (`benchmarks/results/README.md`).

`ej.load("5ak3t/ej", revision="v0.0.1")` downloads only that file and checks it. Architecture and method: technical report

## What ships in this repository

- `ej`: `ej.load(path, low_memory=False)`, `Model.predict`, `Model.adapt` (few-shot option tilt), `AdaptedModel.observe`;
  record validation; Hub download of a repo id's `model.ejpack` (`ej.hub`, file sha256 checked against
  `ej.integrity.KNOWN_PACK_FILES`); the packed format `ejpack v1` (`ej.pack`: one file, every section sha256-checked,
  pickle-free, no base-model download; `low_memory=True` for lower memory); the weights-directory format (safetensors +
  JSON) as a secondary path; integrity checks (runtime modules against `RUNTIME_SHA256`, known releases against
  `ej.integrity`); process hygiene (threads and RNG untouched, bounded encoder memo).
- `ej.train`: `python -m ej.train encoder | teachers | distil | fit`, the training pipeline of this model, with a fit-seed
  knob for replicate fits; `python -m ej.train export` writes the pack of a fitted weights directory (exporting the 0.0.1
  weights directory reproduces the release's content digest).
- `ej.eval`: `python -m ej.eval score` (NLL, micro accuracy, ECE15 with its perfect-calibration floor, certified automation,
  record-cluster CIs, group-macro accuracy with t intervals) and `python -m ej.eval compare` (seed-aware keep rule with
  selection accounting).
- `benchmarks/`: runner, scoring, rival adapters, suite builders with checksums, method notes and aggregate results.

## Verifying weights

`ej.load("5ak3t/ej", revision="v0.0.1")` downloads `model.ejpack` into the Hugging Face cache and refuses it unless its
SHA-256 matches `ej.integrity.KNOWN_PACK_FILES`. Every pack, downloaded or local, is then checked before anything is
decoded: the header digest and the sha256 of every section; for a known state key, the pack's content digest against
`ej.integrity.KNOWN_PACKS`; the runtime modules against `ej/_runtime/RUNTIME_SHA256`. `sha256sum model.ejpack` must print
the SHA-256 above (also listed in the Hub repository's `SHA256SUMS`). Decoding never unpickles. A weights directory is
checked file by file against its `config.json` and `ej.integrity.KNOWN_RELEASES`.

## Provenance

- Model code: commit `f46cf7c` of the maintainers' development repository (not public), with the encoder switch
  `student_lb.CK_DIR` set to `lowbit-b3b010513f948ceb`; `python scripts/state_key.py --git REPO f46cf7c POOL --ck-dir
  lowbit-b3b010513f948ceb --expect 3b3e66d2` recomputes the state key from that tree and the pool. The prediction code is
  `ej/_runtime` of this repository; `python -m ej.train` drives the same fit path.
- Size: counted 10.87 MiB (11.40 MB; a bit-level bound); on disk 11.4 MB (the one file `model.ejpack`, 11,384,312 bytes,
  which is also the whole download); resident (peak live model tensors while predicting) 128 MB, or 35 MB with
  `low_memory=True`. Process memory and latency, with the box: README "Memory and latency of the packed model".

## Known issues

- Low accuracy on unseen workflows (zs_wide final macro_real .419 [.379, .458]); calibrated only on the ticket suites.
- The in-house ticket corpus (Claude Haiku) is not released, so the training pool cannot be rebuilt from public data alone.
- Open licence questions Q1-Q4 are disclosed in `NOTICE`.

## Continuous integration and delivery

`.github/workflows/tests.yml` runs on every push to `main`, on pull requests and on manual dispatch: `lint-and-unit` (file
length rule and the full test suite without weights) and `weights` (downloads `model.ejpack` from the public Hub repository
at `v0.0.1`, checks its SHA-256 and runs the full test suite with `EJ_WEIGHTS` set; no secrets).
`.github/workflows/release.yml` runs on a `v*` tag: both test jobs, then an sdist and a wheel, `SHA256SUMS`, and a GitHub
Release with these notes. Nothing is published to PyPI.
